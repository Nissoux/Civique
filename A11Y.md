# Audit Accessibilité — Civique Web

Cible : WCAG 2.1 AA / RGAA. Audit manuel statique, sans axe-core.

## Périmètre audité

**Pages publiques** : `/` (landing), `/login`, `/register`, `/forgot-password`,
`/reset-password`, `/verify-email`, `/privacy`, `/terms`, `/mentions-legales`,
`/not-found`, `/error`.

**Pages app** : `/app` (dashboard), `/app/exams`, `/app/profile`, `/app/settings`,
et toutes les pages sous `/app/*` (héritent du layout).

**Composants** : `auth/*`, `nav/*`, `brand/*`, `cookie/*`, `social/*`, `profile/*`,
`train/*`, `exam/*`.

## Constats principaux

| Sévérité | Constat | Statut |
|---|---|---|
| Sérieux | Absence d’un lien « Aller au contenu principal » | Corrigé |
| Sérieux | Élément `<main>` manquant / mal placé sur plusieurs pages | Corrigé |
| Sérieux | Champs de formulaire sans `aria-invalid` / `aria-describedby` en erreur | Corrigé |
| Sérieux | `CookieBanner` annoncé comme `role="dialog"` non modal | Corrigé |
| Modéré | `nav` sans `aria-label` (landing, légal, sidebar) | Corrigé |
| Modéré | Anneaux de focus absents sur la sidebar, mobile nav, language picker | Corrigé |
| Modéré | Pas de touche `Escape` sur le `LanguagePicker` | Corrigé |
| Modéré | Logo : texte alternatif redondant (image + wordmark = « Civique Civique ») | Corrigé |
| Mineur | Marquee `WelcomeStrip` : duplicata lu deux fois par les lecteurs d’écran | Corrigé |
| Mineur | `aria-current="page"` manquant sur la navigation active | Corrigé |
| Mineur | Backdrop drawer mobile : `<button>` non sémantique | Corrigé |
| Mineur | SVG décoratifs sans `aria-hidden` ponctuels | Corrigé partiellement |

## Correctifs appliqués

- `app/layout.tsx` — lien skip-to-main visible au focus (sr-only / focus:not-sr-only).
- `app/page.tsx`, `privacy`, `terms`, `mentions-legales`, `not-found`, `error`,
  `components/auth/AuthShell` — un seul `<main id="main-content" tabIndex={-1}>` par page.
- `app/app/layout.tsx` — `<main id="main-content">` partagé par toutes les pages authentifiées.
- `components/auth/TextField`, `PasswordField` — propagation et fusion de `aria-describedby`,
  exposition de l’id du hint, `aria-pressed` sur le toggle œil.
- `components/auth/FormMessage` — accepte un `id`, ajoute `aria-live` (assertive en erreur,
  polite en succès).
- `components/auth/SubmitButton` — `aria-busy` quand `pending`, SVG `aria-hidden`.
- `app/(auth)/login|register|forgot-password|reset-password|verify-email` — relier l’erreur
  aux inputs via `aria-describedby` + `aria-invalid`, `noValidate` (les server actions
  donnent les messages en français).
- `components/profile/ProfileForm`, `ChangePasswordForm`, `DangerZone` — mêmes traitements.
- `components/nav/Sidebar` + `MobileNav` — `nav aria-label`, `aria-current="page"` sur
  lien actif, anneaux de focus visibles (focus-visible:ring-terracotta), `aria-label`
  pour le bouton « Plus », SVG marqués `aria-hidden`, backdrop converti en `<div aria-hidden>`.
- `components/nav/LanguagePicker` — `aria-haspopup="listbox"`, `aria-expanded`,
  `aria-label`, fermeture sur `Escape`, `role="option"` sur les li, `aria-busy`.
- `components/cookie/CookieBanner` — `<aside role="region">` avec `aria-live="polite"`
  (au lieu de `role="dialog"` trompeur), bouton OK avec `aria-label` explicite + focus
  ring.
- `components/brand/Logo` — alt="" quand le wordmark est présent (évite la lecture en
  double), `aria-label` sur le lien sans wordmark, focus ring.
- `components/brand/WelcomeStrip` — duplicata du marquee passé en `aria-hidden`,
  `role="presentation"` + `aria-label` sur le conteneur.
- `components/auth/SocialButtons` — focus ring + SVG `aria-hidden`.
- Pages légales (`privacy`, `terms`, `mentions-legales`) — `nav` du sommaire déjà
  étiquetée ; nav du header étiquetée « Navigation principale ».

## Restent à traiter

- **Modéré — contraste sur l’aubergine** : les sections inversées (hero du dashboard,
  panneau gauche de l’AuthShell, footer) utilisent `text-bone/60` à `/85` sur fond
  aubergine (`#2D1B2E`). À mesurer : la limite WCAG est 4.5:1 pour le texte normal.
  Recommandation : remplacer `text-bone/60` par `text-bone/75` minimum dans le footer
  et les sous-titres pour rester confortable. Non fait ici car nécessite ajustement
  designer global.
- **Modéré — `prefers-reduced-motion`** : la barre `WelcomeStrip` et les animations
  `rise-init` continuent même quand l’utilisateur réduit les mouvements. Solution
  propre : ajouter une règle `@media (prefers-reduced-motion: reduce)` dans
  `globals.css` qui force `animation-duration: 0s` — mais le fichier global est hors
  scope. À faire dans un suivi avec accord designer.
- **Mineur — page mentions-légales** : la section « Éditeur » contient des placeholders
  visibles (`role="note"`). Une fois remplie, le bloc d’alerte saffron doit être
  remplacé par les vraies données.
- **Mineur — exam `QuestionGrid`** : les boutons numérotés ont `aria-label` mais pas
  de `aria-current="true"` sur la question en cours. Le label inclut « (en cours) »,
  ce qui est annoncé correctement, donc acceptable.
- **Mineur — Avatar avec photo** : `<img alt="">` + `aria-hidden` sur l’enveloppe.
  Si l’utilisateur a un avatar de profil personnalisé, le nom est exposé par le contexte
  alentour (ligne d’ami), donc le pattern reste accessible.

## Recommandations de suivi

1. **Test lecteur d’écran réel** — NVDA + Firefox sur Windows, VoiceOver sur Safari/iOS,
   en français et en arabe (RTL) pour valider la lecture des questions traduites.
2. **Tests clavier dédiés** — naviguer toute l’app au clavier ; vérifier le retour
   focus après fermeture du drawer mobile et du LanguagePicker.
3. **Intégration axe-core en CI** — `@axe-core/playwright` ou `jest-axe` sur les
   pages clé pour empêcher les régressions.
4. **Validation contraste** — passer le palette Tisserand dans WebAIM Contrast Checker
   (notamment `text-ink-mute` `#6E5B5F` sur `bone-deep` `#ECE0CB`, et toutes les
   combinaisons sur fond aubergine).
5. **Audit RTL** — vérifier que les contenus traduits en arabe / persan s’affichent
   bien en RTL sur les pages glossaire, fiches et flashcards (déjà fait au niveau
   des balises `lang` / `dir`, mais à confirmer visuellement).
6. **Annoncer les changements de page (SPA)** — sur navigation client Next.js, un
   `aria-live="polite"` sur le `<main>` pourrait aider, mais le `tabIndex={-1}` posé
   permet déjà au lien skip de cibler la zone.
